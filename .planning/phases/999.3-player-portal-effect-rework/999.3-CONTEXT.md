# Phase 999.3: Player portal effect rework - Context

**Gathered:** 2026-07-10
**Status:** Ready for planning (backlog item — not yet scheduled into active milestone)

<domain>
## Phase Boundary

Phase 12에서 완성된 `FloorTransitionEffect`(포탈 진입/퇴장 연출)를 재작업한다. 진입 시 URP 셰이더 기반 소용돌이(vortex) UV 왜곡으로 플레이어와 주변 환경까지 포탈로 빨려들어가는 연출, 퇴장 시 기존 대쉬 애니메이션을 재사용한 수직 도약(머리 위로 짧게 돌진 후 제자리 착지) 연출로 완전히 교체한다.

핵심 불만(출처): 현재 `FloorTransitionEffect`는 `SpriteMask`만 움직이고 플레이어 `Transform` 자체는 고정돼 있어 "빨려들어간다"/"걸어(튀어)나온다"는 느낌이 실제 이동으로 반영되지 않음.

</domain>

<decisions>
## Implementation Decisions

### 진입 연출 (소용돌이 흡입)
- **D-01:** URP 셰이더(소용돌이 UV 왜곡) 기반으로 구현한다. 이 프로젝트에 커스텀 셰이더가 아직 하나도 없어 신규 기술 영역(Shader Graph 또는 HLSL) 추가 작업이 된다는 점을 명확히 인지한 상태에서 확정.
- **D-02:** 플레이어뿐 아니라 주변 환경(타일/파티클)도 함께 포탈로 빨려들어가는 연출을 포함한다 — 범위가 플레이어 단독이 아니라 씬 일부까지 확장된다.
- **D-03:** 기존 `SpriteMask` 경계선 페이드(E1-E4, `PlayEntry()` 전체)는 셰이더 소용돌이 이펙트로 완전히 대체된다 — 겹쳐 쓰지 않음.

### 퇴장 연출 (도약)
- **D-04:** 기존 `CombatController.ExecuteDash()`의 `IsDashing` 애니메이션(대쉬 모션)을 그대로 재사용한다 — 새 애니메이션 클립 제작 불필요, `FastPlayerAnimator.controller`에 이미 `Dash` 상태 존재.
- **D-05:** 이동 궤적은 신규 설계한다 — 포탈에서 머리 위로 짧게 도약(수직 돌진/arc)한 뒤 원래 spawn 위치에 착지. 기존 `ExecuteDash`는 수평 직선 `MovePosition`이므로, 애니메이션(모션 클립)은 재사용하되 이동 궤적 로직은 새로 작성해야 한다.
- **D-06:** 기존 마스크 수축 페이드(`PlayExit()`의 X2/X3, 마스크 생성→수축→정리)는 도약 연출로 완전히 대체된다 — 겹쳐 쓰지 않음.

### 기존 SFX/타이밍
- **D-07:** Phase 13에서 추가된 `AudioManager.PlaySfx(Sfx.PortalEnter/PortalExit)` 호출을 그대로 재사용한다 — 새 사운드 클립 제작/임포트 불필요.
- **D-08:** 새 연출(소용돌이 + 도약)의 전체 길이는 기존 마스크 연출과 비슷하게 유지한다(진입 약 0.4s대, 퇴장 약 0.4~0.5s대) — 전투 템포와 손맛 흐름을 해치지 않는 것이 우선.

### Claude's Discretion
- 정확한 셰이더 구현 방식(Shader Graph vs 직접 HLSL 작성), 소용돌이 강도/반경 튜닝 값
- 주변 환경(타일/파티클)을 "빨려들어가게" 만드는 구체적 방법 — Tilemap 자체를 셰이더로 왜곡할지, 별도 파티클 시스템으로 흉내낼지는 research 단계에서 결정
- 도약 궤적의 정확한 수식(포물선 높이, 지속시간, 이징)
- **미확정 사항 (research/planning에서 재확인 필요):** `PlayExit()`의 X1(퇴장 포탈 이펙트 prefab 성장)/X4(페이드 아웃) — `PortalEffectBuilder`가 만든 포탈 VFX 프리팹 자체의 존치 여부. 대화에서 "마스크 수축 페이드(X1-X4)를 도약이 완전히 대체"로 확인은 받았으나, 이것이 포탈 VFX 오브젝트 자체까지 제거하는 의도인지 마스크 로직(X2/X3)만을 가리킨 것인지 표현이 다소 뭉뚱그려짐 — 포탈 VFX(정적 배경 이펙트)는 유지하고 그 위에 도약이 겹치는 편이 안전한 기본값일 수 있음, 애매하면 사용자에게 재확인.

</decisions>

## Existing Code Insights

### Reusable Assets
- `CombatController.ExecuteDash()`의 `Rigidbody2D.MovePosition()` 보간 패턴 — 퇴장 도약의 이동 구현 참고(단, 궤적은 수평 직선 → 수직 도약으로 신규 설계 필요)
- `IsDashing` 애니메이터 파라미터/`Dash` 상태 — 이미 존재, 재사용
- `AudioManager.PlaySfx(Sfx.PortalEnter/PortalExit)` — 변경 없이 그대로 호출

### Established Patterns
- 이 프로젝트의 모든 연출(HitFreeze, CameraShake, FloorTransitionEffect 등)은 Animator/Timeline이 아니라 코드 코루틴 + `Time.unscaledDeltaTime` + Inspector `[SerializeField]` 튜너블 값 조합으로 구현되어 있음 — 셰이더 파라미터도 동일하게 Inspector에서 튜닝 가능하도록 노출하는 편이 컨벤션에 맞음
- 커스텀 셰이더/머티리얼 에셋은 프로젝트에 전무 — 이번 phase가 최초 도입, 셰이더 컴파일/모바일 성능(Android ARM64 타겟) 영향은 research 단계에서 확인 필요(PROJECT.md 성능 제약)

### Integration Points
- `WorldGenerator.EnterPortal()`/`FloorTransitionSequence()` — `PlayEntry()`/`PlayExit()`를 호출하는 지점, 이번 재작업은 `FloorTransitionEffect`의 내부 구현만 교체하고 호출 시그니처는 유지하는 것이 정밀 변경 원칙에 부합
