## Spacing Scale

Reference resolution: 1920x1080 pixels (Unity Canvas Scaler — Scale With Screen Size, Match Width or Height = 0.5).

All spacing values are multiples of 4 at 1080p. At runtime, Canvas Scaler scales these proportionally.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4 px | Icon gaps, label-to-bar gap |
| sm | 8 px | Inner padding within HUD elements |
| md | 16 px | Gap between HUD groups (floor / gauge / attack type) |
| lg | 24 px | HUD panel inset from screen edges |
| xl | 32 px | Death panel internal padding around restart button |
| 2xl | 48 px | Minimum touch target height for Restart button |
| 3xl | 64 px | Restart button width minimum |

**Exceptions:**
- Restart button touch target: minimum 48x48 px (Unity recommended mobile touch target). Actual button RectTransform must be at least 200x48 px to accommodate label + padding comfortably.
- HUD edge inset: 24 px from all screen edges (conservative — no SafeArea script in Phase 4; MOBI-02 is v2 scope).

## Typography

All sizes in Unity points at 1080p reference resolution via TextMeshProUGUI.fontSize.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| HUD Label | 28 | Bold (700) | 1.2 | Floor counter ("Floor 1"), Attack type label ("LINEAR" / "FAN") |
| HUD Sub-label | 18 | Regular (400) | 1.2 | Gauge label text ("TIME-STOP") if present — optional descriptor above bar |
| Death Heading | 48 | Bold (700) | 1.2 | Not used — death screen shows button only (UI-02: "nothing else required") |
| Button Label | 32 | Bold (700) | 1.0 | Restart button text ("RESTART") |

**Constraint: exactly 3 sizes declared** — 18, 28, 32. (48 heading is reserved-for reference only; UI-02 says no heading is required.)

**Font weight rule: 2 weights only** — Regular (400) for descriptors, Bold (700) for all interactive labels and HUD counters.

**Zero-alloc rule (from STATE.md):** All TextMeshProUGUI updates use `SetText("{0}", value)` with typed overloads. Never string interpolation (`$"Floor {n}"`) in Update.

## Color

All colors expressed as Unity hex (RRGGBB) for `UnityEngine.Color` or Inspector color fields.

| Role | Hex | Alpha | Usage |
|------|-----|-------|-------|

| Secondary — HUD element backgrounds (30%) | #000000 | 0.55 (140/255) | Semi-transparent black backing behind each HUD text group. Image component, Color = (0,0,0,0.55). Ensures readability on any game background without occluding gameplay. |
| Accent — interactive / live data (10%) | #FFFFFF | 1.0 | Floor counter text, attack type label text, gauge fill bar. White on semi-transparent black is max contrast on any background. |
| Destructive | #FF4444 | 1.0 | Not used in Phase 4. No destructive actions. |
| Gauge fill (data-state color) | #FFFFFF | 1.0 | Image.fillAmount bar fill. Same as accent — white bar draining against a #222222 track. |

| Death overlay | #000000 | 0.70 (179/255) | Full-screen Image child of DeathPanel, rendered behind restart button. Dims the frozen game world for readability. Source: RESEARCH.md Open Question 1 — "a semi-transparent dark overlay Image … improves readability massively on any background. This is not polish — it's legibility." |
| Restart button background | #FFFFFF | 1.0 | Button Image, normal color. |
| Restart button label | #000000 | 1.0 | TextMeshProUGUI child of Restart button. Black on white. |
| Restart button highlighted | #CCCCCC | 1.0 | Button ColorBlock highlighted color — visible on touch/hover. |

## Canvas Hierarchy Contract

One Canvas in SampleScene. Render Mode: Screen Space — Overlay (renders above all cameras; no Z-ordering needed).

```
Canvas
  Render Mode: Screen Space — Overlay
  Sort Order: 0
  Canvas Scaler: Scale With Screen Size, Reference 1920x1080, Match 0.5
  ├── HUDPanel                         [always active, no background Image]
  │   ├── FloorGroup                   [anchored: top-left, pos: 24,−24]
  │   │   ├── FloorBacking             [Image, color #000000 alpha 0.55, RectTransform pad sm=8 around children]
  │   │   └── FloorLabel               [TextMeshProUGUI, size 28, Bold, #FFFFFF, text driven by HUDController]
  │   ├── GaugeGroup                   [anchored: top-center, pos: 0,−24]
  │   │   ├── GaugeBacking             [Image, color #000000 alpha 0.55]
  │   │   ├── GaugeTrack               [Image, color #222222, width 200px, height 16px]
  │   │   └── GaugeFill                [Image, Type=Filled, FillMethod=Horizontal, color #FFFFFF, fillAmount driven by HUDController]
  │   └── AttackTypeGroup              [anchored: top-right, pos: −24,−24]
  │       ├── AttackTypeBacking        [Image, color #000000 alpha 0.55]
  │       └── AttackTypeLabel          [TextMeshProUGUI, size 28, Bold, #FFFFFF, text "LINEAR" or "FAN"]
  └── DeathPanel                       [starts inactive, SetActive(true) on PlayerController.OnPlayerDeath]
      ├── DeathOverlay                 [Image, color #000000 alpha 0.70, anchored stretch-full]
      └── RestartButton                [Button, anchored center, RectTransform 240x56 px]
          └── RestartLabel             [TextMeshProUGUI, size 32, Bold, #000000, text "RESTART"]
```

**Anchor rules:**
- FloorGroup: anchor min=(0,1) max=(0,1), pivot=(0,1) — top-left corner, 24px inset.
- GaugeGroup: anchor min=(0.5,1) max=(0.5,1), pivot=(0.5,1) — top-center, 24px from top.
- AttackTypeGroup: anchor min=(1,1) max=(1,1), pivot=(1,1) — top-right corner, 24px inset.
- DeathOverlay: anchor min=(0,0) max=(1,1) — full stretch, covers entire screen.
- RestartButton: anchor min=(0.5,0.5) max=(0.5,0.5), pivot=(0.5,0.5) — dead center of screen.

## HUD Update Rules

| Element | Update Method | Frequency | Allocation |
|---------|--------------|-----------|------------|
| FloorLabel | `SetText("Floor {0}", FloorManager.CurrentFloor)` | Every frame in Update() | Zero — TMP int overload |
| GaugeFill | `_gaugeFill.fillAmount = _gauge.Value` | Every frame in Update() | Zero — float assignment |
| AttackTypeLabel | `SetText(t == AttackType.Linear ? "LINEAR" : "FAN")` | Only when `AttackTypeSelector.Selected` changes (dirty-check with `_lastType`) | Zero — string literal, not interpolation |

**Why poll not event:** GaugeController has no OnValueChanged event. AttackTypeSelector.SetType is called infrequently. Polling in Update() is the established codebase pattern (CombatController). Negligible per-frame cost.

## Interaction Contract

### HUD — Passive Display

No user interaction. HUD is always active during play. No tap targets, no hover states, no transitions.

### Death Screen

| Trigger | Response | Timing |
|---------|----------|--------|
| `PlayerController.OnPlayerDeath` fires | `DeathPanel.SetActive(true)`, `Time.timeScale = 0f`, `Time.fixedDeltaTime = 0f` | Within the same frame as the death event — no animation, no delay |
| Player taps Restart button | `Time.timeScale = 1f`, `Time.fixedDeltaTime = 0.02f`, `FloorManager.CurrentFloor = 1`, `SceneManager.LoadScene(0)` | Immediate on button click — no confirmation dialog, no transition |

**Restart button has no confirmation.** This is not a destructive action in the game sense — it is the only action on the death screen. Confirmation would be an anti-pattern here. Source: REQUIREMENTS.md UI-02 "shows a restart button and nothing else required to understand what to do."

**Time restore before reload is mandatory.** If `Time.timeScale = 0f` at the moment of `SceneManager.LoadScene(0)`, the reloaded scene starts frozen. `timeScale` and `fixedDeltaTime` must always be restored as a pair before the scene load call. Source: RESEARCH.md Pitfall 2.

## Copywriting Contract

| Element | Copy | Notes |
|---------|------|-------|
| Floor counter | "Floor {0}" — e.g., "Floor 1" | Integer substitution via TMP SetText. Always "Floor 1" in Phase 4 (single room). |
| Attack type label | "LINEAR" or "FAN" | All caps. Driven by AttackTypeSelector.Selected. |
| Gauge label (optional) | "TIME-STOP" | Appears above or to the left of the gauge bar as a static descriptor. Optional — include only if space permits without cluttering HUD. |
| Restart button | "RESTART" | All caps. Only text on the death screen. |
| Death screen heading | (none) | UI-02 requirement: "nothing else required to understand what to do." A heading is redundant — the Restart button alone communicates the action. Do not add "YOU DIED" or any heading text in Phase 4. |
| Empty state | (none) | Not applicable — HUD always shows live data. |
| Error state | (none) | Not applicable — no user-facing error states in this phase. TMP magenta quad is a developer error (RESEARCH.md Pitfall 1), not a player-facing state. |
| Destructive actions | (none) | No destructive actions in Phase 4. Restart is not destructive — it is the intended exit from the death state. |
