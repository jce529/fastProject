# Phase 999.4: Enemy AI enhancement pack - Context

**Gathered:** 2026-07-10
**Status:** Ready for planning (backlog item — not yet scheduled into active milestone)

<domain>
## Phase Boundary

Phase 3에서 확립된 근접/원거리 적 FSM(`Idle→Chase→Telegraph→Attack`)에 플레이테스트로 발견된 3가지 개선을 적용한다:
1. 추격/이동 중 낙사해도 죽지 않고 화면 밖에서 "좀비 상태"로 살아있는 문제 해결
2. 근접(Melee) 적의 공격 예고(Telegraph)가 완전 정지 + 0.8초로 너무 관대해 긴장감/속도감이 떨어지는 문제 개선
3. 원거리(Ranged) 적이 제자리에 고정되어 있는 문제 — 플레이어와 거리를 유지하는 키팅(kiting) 이동 도입

세 문제는 서로 독립적인 개선이며 각각 다른 파일/시스템에 걸쳐 있다.

</domain>

<decisions>
## Implementation Decisions

### 낙사 처리
- **D-01:** 예방 + 사후처리 이중화. 근접 적의 기존 `GapAhead`/`TryJump` gap-check 로직을 강화해 애초에 낙사하지 않도록 예방하되, 극단적 지형이나 원거리 적의 신규 키팅 이동 중 등 예외 상황에 대비해 `FallZone` 사후처리도 함께 추가한다.
- **D-02:** `FallZone`에 떨어진 적은 사망 이펙트(파티클/사운드) 없이 즉시 `Destroy` — 화면 밖에서 벌어지는 일이라 연출은 불필요, 단순 제거.
- **D-03:** 이 낙사 처리(예방 + 사후처리)는 근접/원거리 두 타입 모두에 적용한다 — 이번 phase에서 원거리 적도 키팅 이동이 추가되어 동일하게 낙사 위험에 노출되기 때문.

### 공격 예고 타이밍 (근접만)
- **D-04:** 근접 적(`MeleeEnemy`)의 Telegraph 지속시간을 기존 0.8초(Phase 3 D-06)에서 **약 0.4~0.5초**로 단축한다. 정확한 수치는 후속 planning/playtest에서 확정.
- **D-05:** Telegraph 중 완전히 정지하지 않고 **느려진 속도로 계속 이동하며 예고** — "! 아이콘만 뜨고 가만히 서있는" 정적인 느낌을 없애 속도감을 살린다.
- **D-06:** 이번 phase는 **근접(`MeleeEnemy`)만** 대상으로 한다. 원거리(`RangedEnemy`)의 조준 텔레그래프(0.8초, `LineRenderer` 알파 페이드)는 이번 범위에서 변경하지 않는다 — 향후 phase 후보로 별도 분리.

### 원거리 몬스터 포지셔닝 (키팅)
- **D-07:** "근접 적 뒤에 숨는다"는 근접 적의 실제 위치를 추적하는 정교한 엄폐 AI가 아니라, **단순 키팅(플레이어와의 거리 유지 + 플레이어 반대방향 이동)**으로 구현한다. 근접 적 위치는 참조하지 않는다 — 사용자가 명시적으로 이 단순화된 범위를 선택.
- **D-08:** 키팅은 `Chase` 상태 진입 즉시부터 발동한다 — `detectionRadius` 안에 플레이어가 들어오면 공격 사거리와 무관하게 바로 거리 유지 이동을 시작.
- **D-09:** 키팅 이동과 조준/발사(`TelegraphAndFire`)는 병행한다 — 사거리(`aimLineLength`) 안에 들어오면 키팅으로 후퇴 중이라도 조준선이 계속 플레이어를 따라가며 정상적으로 텔레그래프/발사가 진행된다.
- **D-10:** 키팅(후퇴) 시작 거리 임계값은 `aimLineLength`의 약 50% 수준을 기준으로 삼는다(사용자 제안) — 플레이어가 그보다 가까워지면 후퇴 시작. 정확한 수치는 Claude's Discretion.

### Claude's Discretion
- `GapAhead`/`TryJump` gap-check 강화의 구체적 파라미터(감지 거리 확장 여부, 점프력 조정 여부)
- Telegraph 중 이동 속도 배율(예: `chaseSpeed`의 30~50%) 정확한 수치
- Telegraph 지속시간 정확한 값 (0.4~0.5초 범위 내)
- 원거리 적 키팅 이동 속도 값(기존 `moveSpeed=0f`를 대체)
- 키팅 시작 거리 임계값 정확한 수치 (D-10 기준 `aimLineLength`의 대략 50% 근방)
- `FallZone` 적 사후처리 구현 방식 — `FallZoneTrigger`의 태그 체크를 확장할지, Enemy 전용 별도 트리거/컴포넌트를 둘지

</decisions>

## Existing Code Insights

### Reusable Assets
- `FallZoneTrigger.OnTriggerEnter2D`의 태그 체크 패턴 — Enemy 대응 분기를 추가할 때 동일한 트리거 컴포넌트를 확장하거나 나란히 배치 가능
- `MeleeEnemy`의 `_detectionBuffer`/`ContactFilter2D` 사전 할당 패턴 — gap-check 강화나 신규 판정에도 동일 무할당 패턴 재사용
- `RangedEnemy._playerFilter`/`Physics2D.OverlapCircle` 패턴 — 키팅 거리 판정(D-10)에 그대로 재사용 가능

### Established Patterns
- FSM: `enum EnemyState { Idle, Chase, Telegraph, Attack }` + `switch` 기반 `Update()` — 각 Enemy 컴포넌트 내부에서 자체 관리, 변경 시에도 이 구조 유지
- 모든 타이머/코루틴 대기는 `WaitForSecondsRealtime`/`Time.unscaledDeltaTime` — Telegraph 시간 단축(D-04) 및 이동-예고 병행(D-05) 구현 시에도 동일 규칙 적용
- 사망 처리는 `OnDashHit()`에서 Collider 비활성화 + `RigidbodyType2D.Static` + `EnemyDeathEffect` 재생 — 단, 낙사(D-02)는 이 흐름을 타지 않고 단순 `Destroy`로 분기(연출 스킵)

### Integration Points
- `MeleeEnemy.TelegraphAndAttack()` — D-04(시간 단축)/D-05(이동하며 예고) 구현 지점
- `RangedEnemy.UpdateChase()` — D-07~D-09 키팅 로직 추가 지점, 기존 `IsPlayerInRange(aimLineLength)` 체크와 병행 동작해야 함(D-09)
- `FallZoneTrigger.OnTriggerEnter2D` 또는 그 옆의 신규 컴포넌트 — D-01/D-02/D-03 낙사 사후처리 지점
- `MeleeEnemy.GapAhead`/`TryJump` — D-01 예방 로직 강화 지점

<specifics>
## Specific Ideas

- "근접 적 뒤에 숨는다"는 사용자의 원래 표현이었지만, 논의 결과 실제 구현은 근접 적 위치를 참조하지 않는 단순 키팅(거리 유지)으로 범위가 좁혀졌다(D-07) — 더 정교한 "진짜 엄폐" AI는 이번 범위 밖.
- 근접 적의 Telegraph는 "정지 후 예고"에서 "느려진 속도로 이동하며 예고"로 바뀌는 것이 핵심 — 단순히 시간만 줄이는 것보다 이 정지 자체를 없애는 것이 사용자가 지목한 진짜 문제.

</specifics>
