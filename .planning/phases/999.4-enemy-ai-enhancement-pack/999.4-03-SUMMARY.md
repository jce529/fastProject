# Phase 999.4 Plan 03: MeleeEnemy 텔레그래프 이동형 재작성 Summary

**MeleeEnemy의 Telegraph가 "완전 정지 + 0.8초"에서 "느려진 속도로 이동하며 예고 + 0.45초"로 재작성되었고, 플레이테스트로 D-04/D-05/D-06 전 항목이 통과 확인되었다.**

## Performance

- **Duration:** Task 1 코드 작성 (2026-07-12) + Task 2 사용자 플레이테스트 승인 (2026-07-14, 별도 세션)
- **Tasks:** 2 (1 auto + 1 checkpoint:human-verify)
- **Files modified:** 1

## Accomplishments
- `TelegraphAndAttack()`이 `RangedEnemy.TelegraphAndFire()`와 동일한 `while (elapsed < telegraphDuration)` per-frame 루프 구조로 재작성됨 (D-04)
- Telegraph 지속시간이 0.8초 → 0.45초로 단축됨 (D-04)
- Telegraph 중 적이 멈추지 않고 `chaseSpeed * 0.4` 속도로 플레이어를 향해 계속 이동하며, 매 프레임 `FlipSprite(dirX)`로 스프라이트가 방향에 맞게 반전됨 (D-05) — 기존엔 이 코루틴에서 FlipSprite가 호출되지 않았음
- Attack 단계(윈드업+히트박스)는 기존처럼 정지 상태를 유지 — Telegraph만 이동, 한 글자도 바뀌지 않음
- `RangedEnemy.cs`는 이 Plan에서 전혀 수정되지 않음 — 원거리 적 조준 텔레그래프(0.8초, LineRenderer) 회귀 없음 확인 (D-06)
- 플레이테스트 중 발견된 "!" 아이콘 미표시 문제(ExclamationIcon 스프라이트 미할당)는 이 Plan의 코드 문제가 아니라 사전부터 있던 프리팹 애셋 누락으로 확인 — quick task 260714-fnr로 별도 수정 완료

## Files Created/Modified
- `Assets/Scripts/Enemy/MeleeEnemy.cs` - Added `telegraphDuration`(0.45f)/`telegraphSpeedMultiplier`(0.4f) `[SerializeField]` fields; rewrote `TelegraphAndAttack()` to replace the blocking `WaitForSecondsRealtime(0.8f)` with a per-frame `while` loop that moves the enemy toward the player and calls `FlipSprite(dirX)` each frame; `IsAlive` guard now checked every loop iteration. Fixed separately via quick task 260714-fnr (commit `93a3d99`) rather than folding into this plan, per surgical-change principle.
