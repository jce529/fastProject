<task type="auto">
  <name>Task 2: CombatController — _isAttackPending으로 상태 분리, ExitAttackPending() 도입</name>
  <files>Assets/Scripts/Player/CombatController.cs</files>
  <action>
현재 문제: `ExitSlowMotion()`이 항상 `_rangeDisplay.Hide()` + `_lastHighlighted.ClearHighlight()` + `_lastHighlighted = null`을 실행한다. 게이지 소진 경로(`if (_isSlowMo && _gauge.IsEmpty) ExitSlowMotion()`)에서도 마찬가지로 범위 표시가 사라진다.

디자인 의도: 게이지 소진 → 슬로우모션만 해제, 범위 표시·하이라이트·대시 대기 상태는 유지.

**변경 목록 (외과적 수정):**

1. **필드 추가** (`// -- State` 블록):
   ```csharp
   private bool _isAttackPending; // true: attack 버튼이 눌린 채 대시 대기 중
   ```
   `_slowMoCancelledByRoll` 필드는 **제거**한다 (역할이 `_isAttackPending`으로 흡수됨).

2. **EnterSlowMotion() 수정**: 기존 동작 유지. 단, 호출 시점에 맞춰 `_isAttackPending = true;`를 추가한다.
   ```csharp
   private void EnterSlowMotion()
   {
       if (_isSlowMo) return;
       _isAttackPending = true;   // ← 추가
       Time.timeScale = slowTimeScale;
       // ... 나머지 기존 코드 유지
   }
   ```

3. **ExitSlowMotion() 수정**: timeScale 복원만 담당. `_rangeDisplay.Hide()`, highlight clear 코드를 **제거**한다.
   ```csharp
   private void ExitSlowMotion()
   {
       if (!_isSlowMo) return;
       Time.timeScale = 1f;
       Time.fixedDeltaTime = 0.02f;
       _isSlowMo = false;
       // _rangeDisplay.Hide() 및 highlight clear 줄 삭제
   }
   ```

4. **ExitAttackPending() 신규 추가**: 범위 표시·하이라이트 정리를 이곳에서만 담당한다.
   ```csharp
   private void ExitAttackPending()
   {
       if (!_isAttackPending) return;
       _isAttackPending = false;
       _rangeDisplay?.Hide();
       if (_lastHighlighted != null)
       {
           _lastHighlighted.ClearHighlight();
           _lastHighlighted = null;
       }
   }
   ```

5. **Update() 수정**:

   a. Roll 처리 블록: `ExitSlowMotion()` 호출 후 `_slowMoCancelledByRoll = true` 대신 `ExitAttackPending()` 호출.
   ```csharp
   if (_isSlowMo && input.RollPressed)
   {
       ExitSlowMotion();
       ExitAttackPending();   // 범위 표시 해제 + 대시 대기 종료
       return;
   }
   ```

   b. 하이라이트 갱신 조건: `_isSlowMo` → `_isAttackPending`으로 변경 (게이지 소진 후에도 하이라이트 유지).
   ```csharp
   if (_isAttackPending && !_isBusy)
       UpdateHighlight(FindNearestEnemyInRange());
   ```

   c. 게이지 소진 경로: `ExitSlowMotion()`만 호출 (범위 표시는 유지됨 — 이미 수정된 ExitSlowMotion은 hide 안 함).
   ```csharp
   if (_isSlowMo && _gauge.IsEmpty)
       ExitSlowMotion(); // _isAttackPending은 true 유지 → 범위 표시·하이라이트 남음
   ```

   d. 빠른 탭 경로 (`_isSlowMo && !input.IsAttackDown && !input.AttackReleased`): 동일하게 `ExitSlowMotion()`만. (release event가 없는 경로이므로 AttackReleased 블록이 대신 ExitAttackPending을 처리함.)

   e. AttackReleased 블록: `_slowMoCancelledByRoll` 체크를 **제거**하고, `ExitAttackPending()`을 추가한다.
   ```csharp
   if (input.AttackReleased)
   {
       IEnemy cachedTarget = _lastHighlighted;
       if (_isSlowMo) ExitSlowMotion();

       if (!_isAttackPending)   // 이미 roll 등으로 대시 대기가 취소된 경우
       {
           Debug.Log("[Combat] Attack released but attack pending was already cancelled.");
           return;
       }

       ExitAttackPending();
       StartCoroutine(DashOrWhiff(cachedTarget));
   }
   ```

   f. `EnterSlowMotion()` 호출 조건에 `!_isAttackPending` 추가 (중복 진입 방지, 이미 EnterSlowMotion 내부에 _isSlowMo guard가 있으나 명시적으로 통일).
      현재: `if (input.AttackHeld && !_isSlowMo && _attackCooldown <= 0f)`
      변경: `if (input.AttackHeld && !_isSlowMo && !_isAttackPending && _attackCooldown <= 0f)`

   g. 게이지 drain 조건: 기존 `input.IsAttackDown && _attackCooldown <= 0f` — 변경 없음 (`_isAttackPending` 상태와 무관하게 버튼이 눌린 동안만 소모).

변경하지 않는 것: DashOrWhiff 코루틴 내부, ExecuteDash, ExecuteWhiff, HitFreeze, FindNearestEnemyInRange, IsInAttackShape, safety timeout 로직.
