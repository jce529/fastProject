# /gsd:clarify-vague

<objective>
사용자의 추상적인 아이디어를 '실제 어떤 동작이 일어나야 하는가'라는 기능적 요구사항으로 빠르게 해체합니다. 아키텍처 설계보다는 **'무엇이 만들어져야 하는가'**를 확정하는 데 집중합니다.
</objective>

<process>
1. **아이디어 핵심 파악**: 사용자가 말한 3~4가지 핵심 기능의 리스트를 뽑아냅니다.
2. **동작 방식 역질문 (Reverse-Questioning)**: 
   - 각 기능이 게임 내에서 어떻게 작동해야 하는가? (속도, 버튼, 반응 등)
   - 사용자가 화면에서 무엇을 보게 되는가?
   - 성공적으로 구현되었다고 판단할 기준은 무엇인가?
3. **기능 리스트 확정**: 논의된 내용을 바탕으로 구현할 기능의 범위를 확정합니다.
4. **Handover**: 바로 `/gsd:plan-vague`로 넘어가 작업을 쪼갭니다.

*주의: 이 커맨드는 사용자 의도를 파악하는 능력이 좋은 **Claude 3 Opus**에서 실행하십시오.*
</process>

<success_criteria>
- 구현해야 할 구체적인 기능 목록 확보.
- 각 기능의 상세 동작 방식(Input/Output/Behavior) 합의.
- 아키텍처 논의 없이 바로 구현 단계로 진입 가능한 상태.
</success_criteria>
