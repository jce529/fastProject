# 프로토타입 기획서  
## 프로젝트 가칭: 미정

---

# 1. 프로토타입 목적

이 프로토타입의 목적은 완성형 게임을 만드는 것이 아니라, 핵심 게임성이 실제로 재미있는지 검증하는 것이다.

가장 중요한 검증 대상은 다음이다.

1. **공격 버튼을 누르면 슬로우 모션이 걸리고, 손을 떼면 적에게 돌진하는 전투가 재미있는가?**
2. **직선형 공격 범위와 부채꼴형 공격 범위 중 어떤 것이 더 모바일에 적합한가?**
3. **원샷원킬 구조가 모바일 조작에서 불쾌하지 않은가?**
4. **무한 탑 등반 구조가 자연스럽게 이어지는가?**
5. **적을 모두 죽이지 않아도 되는 등반형 플레이가 재미있는가?**
6. **낙사 시 즉사하지 않고 직전 플랫폼으로 복귀하는 방식이 액션감을 해치지 않는가?**

---

# 2. 게임 개요

## 장르

모바일 2D 가로 화면 플랫포머 액션 게임

## 핵심 콘셉트

플레이어는 끝없이 이어지는 탑을 올라간다.  
각 층에는 적과 플랫폼, 사다리, 계단 등이 배치되어 있으며, 플레이어는 적을 모두 죽일 필요 없이 위쪽 출구 지점에 도달하면 다음 층으로 이동한다.

전투는 원샷원킬 방식이다.

```text
플레이어가 맞으면 즉사
적이 맞으면 즉사
```

플레이어는 공격 버튼을 누르고 있는 동안 슬로우 모션 상태에서 공격 범위를 확인하고, 손을 떼면 범위 안의 가장 가까운 적에게 돌진하여 처치한다.

---

# 3. 핵심 플레이 문장

**빠르게 뛰어다니며 탑을 오르고, 공격 버튼으로 시간을 느리게 만든 뒤, 범위 안의 적에게 돌진해 한 방에 처치하는 모바일 2D 등반 액션 게임.**

# 6. 기본 게임 루프

프로토타입의 기본 흐름은 다음과 같다.

```text
1. 게임 시작
2. 공격 타입 선택
   - 직선형
   - 부채꼴형

3. 첫 번째 층 진입
4. 적과 지형이 배치됨
5. 플레이어가 이동, 점프, 공격을 사용해 위쪽 출구로 이동
6. 필요하면 적을 처치
7. 필요 없으면 적을 피하고 등반
8. 위쪽 출구 도달
9. 조작 불가 상태로 전환
10. 플레이어가 다음 층 시작 위치로 순간이동
11. 카메라가 위로 이동
12. 다음 층의 가림막이 사라짐
13. 카메라 전환 완료
14. 적이 플레이어를 인식하기 시작
15. 조작 가능
16. 반복
17. 플레이어 사망 시 게임 종료 또는 재시작
```

# 7. 승리/패배 조건

## 프로토타입 목표

프로토타입은 최종 엔딩이 없는 구조로 한다.

목표는 최대한 높은 층까지 올라가는 것이다.

## 층 클리어 조건

프로토타입에서는 다음 조건을 사용한다.

```text
위쪽 출구 지점 도달
```

적을 모두 처치할 필요는 없다.

## 사망 조건

플레이어는 다음 상황에서 사망한다.

```text
적의 공격에 맞음
적의 투사체에 맞음
위험 오브젝트에 피격됨
```

단, 낙사는 사망으로 처리하지 않는다.

# 8. 플레이어 조작

## 기본 조작

모바일 가로 화면 기준.

왼쪽 영역:

```text
좌우 이동
```

오른쪽 영역:

```text
점프 버튼
공격 버튼
구르기 버튼
```

## 별도 대시 버튼 없음

이 게임에는 별도의 대시 버튼을 넣지 않는다.

대시 역할은 공격 시스템이 담당한다.

## 구르기 (Roll)

공격 버튼과는 별개로 구르기 버튼이 존재한다.

구르기는 회피기로, 공격 돌진과는 다른 이동 수단이다.

```text
구르기 버튼 입력
→ 짧은 구르기 이동
→ 구르기 중 무적 (i-frame)
```

구르기 도중 공격 버튼을 누르고 있었다면 슬로우 모션이 취소된다.
공격 판정은 발동하지 않고, 구르기가 우선된다.

PC 테스트 기준 입력: Shift 키. 모바일에서는 전용 버튼으로 전환 예정.

```text
공격 버튼 누름
→ 슬로우 모션
→ 공격 범위 표시
→ 손을 뗌
→ 적에게 돌진
```

즉, 플레이어의 대시는 이동기가 아니라 공격의 일부다.

# 9. 플레이어 이동 시스템

## 기본 이동

플레이어는 기본적으로 빠르게 뛰어다닌다.

목표는 일반 이동만으로도 속도감이 느껴지게 만드는 것이다.

```text
기본 이동 속도 빠름
가속감 있음
조작 반응 즉각적
점프 후 공중 제어 가능
```

## 점프

점프는 플랫포머 기본 조작으로 사용한다.

프로토타입에서는 우선 단순 점프로 시작한다.

포함하지 않을 것:

```text
이단 점프
벽점프
벽타기
공중 대시
```

이 기능들은 추후 업데이트 후보로 둔다.

# 10. 낙사 처리

## 기본 규칙

낙사 시 플레이어는 사망하지 않는다.

대신 마지막으로 밟은 플랫폼으로 되돌아간다.

```text
플레이어가 플랫폼에 착지
→ 해당 플랫폼 위치 저장

플레이어가 낙사 구역으로 떨어짐
→ 마지막 플랫폼 위치로 복귀
→ 짧은 무적 부여
```

## 목적

낙사를 즉사로 처리하지 않는 이유는 다음과 같다.

```text
액션감을 시원하게 유지하기 위해
모바일 조작 스트레스를 줄이기 위해
원샷원킬 전투의 가혹함을 완화하기 위해
플레이어가 과감하게 점프하고 이동하도록 유도하기 위해
```

## 직전 플랫폼 저장 기준

프로토타입에서는 단순하게 처리한다.

```text
마지막으로 밟은 플랫폼 = 복귀 지점
```

플랫폼에 착지할 때마다 해당 위치를 저장한다.

## 낙사 복귀 후 처리

낙사 후 복귀하면 짧은 무적을 준다.

목적:

```text
복귀 직후 적에게 즉시 맞아 죽는 상황 방지
억울한 사망 방지
플레이 흐름 유지
```

프로토타입 테스트용 수치 예시:

```text
낙사 복귀 후 무적: 0.7초 ~ 1.0초
복귀 후 조작: 즉시 가능
```

수치는 테스트 후 조정한다.

# 11. 전투 시스템

## 원샷원킬

전투의 기본 규칙은 단순하다.

```text
플레이어 피격 = 즉시 사망
적 피격 = 즉시 사망
```

## 플레이어 공격 구조

플레이어 공격은 다음 흐름으로 작동한다.

```text
1. 공격 버튼을 누른다.
2. 슬로우 모션이 발동한다.
3. 플레이어 전방에 공격 범위가 표시된다.
4. 플레이어가 손을 뗀다.
5. 공격 범위 안의 적을 검사한다.
6. 범위 안에 적이 있으면 가장 가까운 적을 선택한다.
7. 플레이어가 대상에게 돌진한다.
8. 돌진 중 플레이어는 무적이다.
9. 대상에게 닿으면 적이 사망한다.
10. 공격 후 짧은 딜레이가 발생한다.
```

## 공격 범위 안에 적이 없을 경우

공격 범위 안에 적이 없다면 돌진하지 않는다.

```text
범위 안에 적 없음
→ 짧은 헛베기
→ 헛베기 후 딜레이
```

이렇게 하는 이유는, 적이 없을 때도 돌진이 가능하면 사실상 대시 버튼처럼 쓰일 수 있기 때문이다.

이 게임에서는 대시를 공격에 제한하고 싶기 때문에, 적이 없을 때는 이동용 돌진이 발생하지 않는다.

# 12. 공격 타입

프로토타입에서는 공격 타입을 두 가지 모두 구현한다.

```text
직선형
부채꼴형
```

## 선택 방식

프로토타입에서는 게임 시작 전 선택 방식으로 한다.

```text
게임 시작
→ 공격 타입 선택
→ 선택한 타입으로 플레이
```

향후 업데이트에서는 다음 방식으로 확장할 수 있다.

```text
무기별 공격 타입
캐릭터별 공격 타입
플레이 중 교체
층 진입 전 선택
아이템 획득으로 변경
```

---

## 12-1. 직선형 공격

### 개념

플레이어 전방으로 길고 좁은 공격 범위를 표시한다.

```text
플레이어 → ━━━━━━━━━
```

### 특징

직선형 공격은 정밀하고 공격적인 플레이에 적합하다.

### 장점

```text
멀리 있는 적을 노리기 좋음
원하는 적을 비교적 정확히 선택 가능
돌진 공격의 속도감이 잘 살아남
고수 플레이에 적합
```

### 단점

```text
위아래 판정이 좁으면 모바일에서 어렵게 느껴질 수 있음
다수의 적이 흩어져 있을 때 대응이 어려움
```

### 공격 방향 기준

공격 범위의 방향은 플레이어가 지정한 방향으로 결정된다.

```text
PC 테스트 기준: 마우스 커서 방향
모바일 기준: 터치 드래그 방향 (추후 전환)
```

공격 버튼을 누른 채 방향을 조준하고, 손을 떼면 해당 방향의 적에게 돌진한다.

### 프로토타입 구현 방향

프로토타입에서는 너무 얇은 직선이 아니라, 약간의 두께가 있는 직선 범위로 만든다.

```text
전방 거리 + 위아래 허용 폭 (반각 30도)
```

즉, 실제 판정은 얇은 선이 아니라 캡슐형에 가까운 직선 판정으로 잡는다.

---

## 12-2. 부채꼴형 공격

### 개념

플레이어 전방으로 넓게 퍼지는 공격 범위를 표시한다.

```text
     ＼ | ／
플레이어 →
     ／ | ＼
```

### 특징

부채꼴형 공격은 안정적인 조작과 넓은 포착 범위에 적합하다.

### 장점

```text
모바일 조작에 친화적
근처 적을 잡기 쉬움
수직 위치 차이가 있는 적도 포착 가능
난전 상황에서 사용하기 편함
```

### 단점

```text
원하지 않은 가까운 적에게 돌진할 수 있음
정밀한 타깃 선택은 직선형보다 어려움
범위가 너무 넓으면 게임이 쉬워질 수 있음
```

### 프로토타입 구현 방향

부채꼴형은 너무 넓지 않게 시작한다.

테스트 목적은 다음이다.

```text
모바일에서 부채꼴형이 더 편한가?
자동 타깃팅과 충돌하지 않는가?
너무 쉬워지지 않는가?
직선형보다 더 재미있는가?
```

# 13. 타깃 선택 규칙

공격 버튼에서 손을 뗐을 때, 공격 범위 안의 적을 검사한다.

## 타깃 선택 기준

```text
공격 범위 안에 있는 적 중
플레이어와 가장 가까운 적
```

## 우선순위

프로토타입에서는 단순하게 거리 기준만 사용한다.

```text
1순위: 공격 범위 안에 있는가?
2순위: 플레이어와 가장 가까운가?
```

추후에는 다음 요소를 추가할 수 있다.

```text
플레이어가 바라보는 방향과 더 가까운 적 우선
조준선 중앙에 가까운 적 우선
위험도가 높은 적 우선
원거리 적 우선
```

하지만 프로토타입에서는 단순 거리 우선으로 검증한다.

# 14. 돌진 공격

## 기본 규칙

대상이 선택되면 플레이어는 해당 적에게 빠르게 돌진한다.

```text
타깃 선택
→ 플레이어가 타깃 방향으로 고속 이동
→ 돌진 중 무적
→ 타깃에게 닿으면 적 사망
```

## 돌진 중 무적

돌진 중에는 플레이어가 무적이다.

목적:

```text
패링 없이 공격적인 회피 가능
빠른 액션감 제공
원샷원킬의 부담 완화
적의 공격을 뚫고 들어가는 쾌감 제공
```

## 무적 적용 범위

프로토타입에서는 다음 구간에만 무적을 적용한다.

```text
돌진 시작
→ 타깃에게 도달
→ 공격 판정 발생 직후 아주 짧은 시간
```

돌진이 끝난 뒤에는 기본적으로 무적이 풀린다.

단, 정확한 후무적 시간은 테스트하면서 조정한다.

# 15. 공격 후 딜레이 및 히트 프리즈

## 히트 프리즈 (Hit-Freeze)

적을 처치했을 때 순간적으로 세계가 멈추는 연출이 발동한다.

```text
돌진 성공 → 적 사망 처리 → timeScale=0 (75ms) → 세계 재개
```

목적:

```text
타격감과 손맛 강화
처치 순간의 쾌감을 강조
슬로우 모션과 조합한 리듬감 연출
```

프로토타입 수치:

```text
히트 프리즈 지속시간: 75ms (0.075초)
```

## 방향

공격 후에는 짧은 딜레이가 존재한다.

다만 성공 공격과 실패 공격의 딜레이를 다르게 둔다.

```text
적 처치 성공: 짧은 딜레이
헛베기: 더 긴 딜레이
```

## 이유

이렇게 하는 이유는 다음과 같다.

```text
성공적인 공격은 빠르고 시원하게 느껴지게 하기 위해
헛공격에는 리스크를 주기 위해
무한 연속 돌진으로 게임이 너무 쉬워지는 것을 막기 위해
```

## 프로토타입 테스트용 수치

초기 테스트용 수치는 다음 정도로 시작한다.

```text
처치 성공 후 딜레이: 0.15초 ~ 0.25초
헛베기 후 딜레이: 0.35초 ~ 0.5초
```

정확한 값은 실제 플레이 테스트 후 조정한다.

# 16. 슬로우 모션 / 시간정지 게이지

## 기본 방향

공격 버튼을 누르고 있는 동안 슬로우 모션이 발동한다.

슬로우 모션은 시간정지용 게이지를 사용한다.

```text
공격 버튼 누름
→ 슬로우 모션 발동
→ 시간정지 게이지 소모
→ 공격 범위 표시
```

## 중요한 규칙

시간정지 게이지는 슬로우 모션을 위한 자원이다.  
공격 자체는 유지한다.

즉, 게이지가 부족하거나 슬로우가 끝나더라도 공격 입력 자체가 바로 사라지는 구조는 피한다.

현재 해석 기준으로는 다음 방식이다.

```text
게이지가 있는 동안:
- 슬로우 모션 적용
- 공격 범위 표시 유지

게이지가 끝났을 때:
- 슬로우 모션은 해제
- 공격 조준 상태는 유지 가능
- 손을 떼면 공격은 발동
```

이 부분은 실제 구현 전에 한 번 더 확인이 필요하다.  
제가 이해한 방향은 **“게이지는 슬로우에만 관여하고, 공격 가능 여부 자체를 막지는 않는다”**입니다.

## 최대 지속시간

슬로우 모션에는 최대 지속시간이 있다.

무한히 시간을 느리게 유지할 수 없다.

```text
공격 버튼을 계속 누르고 있어도
정해진 시간이 지나면 슬로우 모션은 해제된다.
```

## 게이지 회복 방식 (확정)

시간정지 게이지는 두 가지 방식으로 회복된다.

```text
자동 회복: 공격 버튼에서 손을 떼면 자동으로 차오름 (~6.7초에 완충)
처치 보너스: 적을 한 명 처치할 때마다 즉시 +20% 회복
```

게이지가 없어도 공격 버튼 입력은 유지된다.  
슬로우 모션만 해제될 뿐, 손을 떼면 돌진은 발동한다.

## 프로토타입 테스트용 수치

```text
슬로우 최대 지속시간: 4초 (게이지 전량 소모 기준)
슬로우 배율: 20% (timeScale = 0.2)
게이지 소모 속도: 초당 25% (4초에 완전 소진)
게이지 자동 회복 속도: 초당 15% (~6.7초에 완충)
처치 보너스 회복량: +20%
```

# 17. 적 시스템

프로토타입에서는 적을 많이 넣지 않는다.

우선 핵심 전투를 검증하기 위해 2종을 구현한다.

```text
근접형 적
원거리형 적
```

돌진형 적은 재미있을 수 있지만, 프로토타입 초기에는 플레이어의 돌진 시스템과 겹칠 수 있으므로 후순위로 둔다.

---

## 17-1. 근접형 적

### 역할

가장 기본적인 적이다.

플레이어에게 접근하고, 가까워지면 공격한다.

### 행동

```text
플레이어 인식
→ 접근
→ 공격 거리 진입
→ 공격 예고
→ 근접 공격
```

### 특징

```text
한 방에 죽음
플레이어를 한 방에 죽임
공격 전 예고 모션 필요 ("!" 아이콘, 0.8초)
처치 시 Die 애니메이션 재생 후 씬에 정지 상태로 남음 (즉시 삭제 없음)
```

### 목적

```text
기본 회피와 공격 테스트
돌진 공격 타깃 역할
다수 배치 시 압박 제공
```

---

## 17-2. 원거리형 적

### 역할

플레이어의 이동과 등반을 방해하는 적이다.

### 행동

```text
플레이어 감지 범위(detectionRadius) 진입
→ Chase 상태 (플레이어 추적)
→ 공격 트리거 범위(aimLineLength) 진입
→ 조준선 페이드인 (0.8초)
→ 투사체 발사
→ Idle 복귀
```

감지 범위와 공격 트리거 범위는 별도로 조정 가능하다.

```text
detectionRadius: 플레이어를 인식하고 추적 시작하는 거리
aimLineLength:   이 거리 이내에서만 조준선 표시 및 발사
```

감지 범위 밖으로 나가면 Chase를 멈추고 Idle로 복귀한다.

### 특징

```text
한 방에 죽음
투사체에 맞으면 플레이어 즉사
공격 전 조준선 표시 필요 (0.8초 페이드인 후 발사)
처치 시 Die 애니메이션 재생 후 씬에 정지 상태로 남음 (즉시 삭제 없음)
```

### 목적

```text
슬로우 모션 사용 유도
위험한 적 선제 제거 유도
플레이어가 적을 죽일지 피할지 판단하게 만듦
```

# 18. 적 인식 타이밍

## 중요한 규칙

층 이동 중에는 플레이어가 조작 불가능하다.  
따라서 이 시간 동안 적이 플레이어를 공격하면 불공정하다.

그래서 적은 카메라 전환이 완료된 뒤부터 플레이어를 인식한다.

## 층 이동 중 적 상태

```text
플레이어 출구 도달
→ 층 전환 시작
→ 플레이어 조작 불가
→ 플레이어 다음 층 시작 위치로 순간이동
→ 카메라 이동
→ 다음 층 가림막 해제
→ 카메라 전환 완료
→ 적 인식 활성화
→ 플레이어 조작 가능
```

## 적 인식 시작 조건

```text
카메라 전환 완료
+ 플레이어 조작 가능 상태 진입
```

이 시점부터 적이 플레이어를 추적하거나 공격할 수 있다.

# 19. 층 구조

## 기본 방향

게임은 무한히 이어지는 탑처럼 보이지만, 실제로는 층 단위로 생성하고 관리한다.

프로토타입에서는 현재 층과 다음 층 정도만 관리해도 충분하다.

```text
현재 층
다음 층
필요 시 이전 층 제거 또는 비활성화
```

## 층 프리셋

층은 완전 랜덤 생성이 아니라 프리셋 기반으로 만든다.

```text
수작업 층 구조
+ 적 위치 일부 랜덤화
+ 출구 위치 지정
```

## 층 이동 요소

층마다 다음 요소가 다르게 등장한다.

```text
플랫폼
사다리
계단
```

각 층 프리셋마다 이동 방식이 다르다.

예시:

```text
플랫폼 중심 층
사다리 중심 층
계단 중심 층
혼합 층
낙사 구역이 있는 층
```

---

# 20. 프로토타입 층 프리셋 예시

## 프리셋 1: 기본 플랫폼 층

목적:

```text
기본 이동, 점프, 공격 테스트
```

구성:

```text
넓은 바닥
중간 플랫폼 2~3개
상단 출구
근접형 적 2마리
```

---

## 프리셋 2: 사다리 층

목적:

```text
수직 이동 중 적 회피 테스트
```

구성:

```text
중앙 사다리
좌우 보조 플랫폼
상단 출구
근접형 적 1마리
원거리형 적 1마리
```

---

## 프리셋 3: 계단형 층

목적:

```text
빠른 이동과 경로 선택 테스트
```

구성:

```text
좌우로 꺾인 계단형 플랫폼
상단 출구
근접형 적 2마리
원거리형 적 1마리
```

---

## 프리셋 4: 낙사 위험 층

목적:

```text
낙사 복귀 시스템 테스트
```

구성:

```text
깊은 낙사 구역
좁은 플랫폼
상단 출구
원거리형 적 1~2마리
```

낙사 시:

```text
마지막으로 밟은 플랫폼으로 복귀
짧은 무적 부여
```

---

## 프리셋 5: 혼합 층

목적:

```text
실제 게임 흐름 테스트
```

구성:

```text
플랫폼 + 사다리 + 계단 혼합
상단 출구
근접형 적 2마리
원거리형 적 2마리
```

# 21. 층 전환 시스템

## 출구 도달

프로토타입에서는 위쪽 출구 지점에 닿으면 즉시 층 전환이 시작된다.

```text
출구 도달
→ 즉시 층 전환
```

상호작용 버튼은 사용하지 않는다.

## 층 전환 연출

층 전환은 방을 넘어가는 것처럼 연출한다.

```text
다음 층은 처음에 가려져 있음
출구에 도달하면 카메라가 위로 이동
가림막이 사라지며 다음 층 공개
```

## 처리 순서

```text
1. 플레이어가 출구 지점에 닿는다.
2. 플레이어 조작을 막는다.
3. 플레이어를 다음 층 시작 위치로 순간이동시킨다.
4. 카메라가 다음 층으로 이동한다.
5. 다음 층 가림막이 사라진다.
6. 카메라 전환이 완료된다.
7. 적 인식을 활성화한다.
8. 플레이어 조작을 다시 허용한다.
```

## 중요한 규칙

```text
카메라 전환 중 적은 플레이어를 인식하지 않는다.
카메라 전환 중 플레이어는 조작할 수 없다.
카메라 전환 완료 후부터 적이 행동한다.
```

# 22. 이전 층 처리

플레이어는 이전 층으로 돌아갈 수 없다.

층 이동이 완료되면 이전 층은 제거하거나 비활성화한다.

```text
이전 층 복귀 불가
이전 층 적 비활성화
이전 층 오브젝트 제거 또는 풀 반환
```

모바일 성능을 위해 지나간 층을 계속 유지하지 않는다.

# 23. 그래픽 스타일

## 방향

단순한 실루엣 스타일.

## 이유

```text
모바일 화면에서 시인성이 좋음
제작 부담이 낮음
빠른 출시 목표와 잘 맞음
액션과 공격 범위가 잘 보임
슬로우 모션 연출과 잘 어울림
```

## 기본 시각 규칙

프로토타입 기준 색상 규칙은 다음처럼 잡을 수 있다.

```text
플레이어: 밝은 색 실루엣
적: 어두운 색 또는 붉은 계열 실루엣
위험 요소: 빨간색
공격 범위: 파란색, 청록색, 흰색 계열
출구: 노란색 또는 밝은 강조색
배경: 어두운 단색 또는 그라데이션
```

이 색상은 확정이 아니라 시인성 테스트용 기준이다.

# 25. 사망 및 재시작

```text
사망

```

# 27. 난이도 설계

## 기본 방향

체력 증가로 난이도를 올리지 않는다.  
모든 적은 한 방에 죽는다.

난이도는 다음 요소로 조절한다.

```text
적 수 증가
원거리 적 비율 증가
플랫폼 구조 복잡화
낙사 구역 증가
출구까지의 경로 복잡화
안전한 플랫폼 감소
적 배치 조합 변화
```

## 프로토타입 난이도 흐름 예시

```text
1~3층:
- 근접형 적 위주
- 단순 플랫폼

4~6층:
- 원거리형 적 등장
- 사다리/계단 구조 등장

7~10층:
- 근접형 + 원거리형 조합
- 낙사 구역 등장

11층 이후:
- 프리셋 반복
- 적 수 증가
- 원거리형 비율 증가
```

# 28. 모바일 성능 설계

## 기본 원칙

무한 탑이지만 실제로 전체 탑을 만들지 않는다.

```text
현재 층과 다음 층만 유지
이전 층은 제거 또는 비활성화
적과 이펙트는 재사용
```

## 최적화 대상

```text
적 오브젝트
투사체
공격 이펙트
사망 이펙트
가림막 연출
층 프리셋
```

## 추천 방식

```text
오브젝트 풀링 사용
화면 밖 오브젝트 비활성화
이전 층 제거
파티클 최소화
단순한 실루엣 그래픽 사용
```

# 32. 아직 확인이 필요한 부분

아래는 제가 임의로 확정하지 않고 남겨두는 부분입니다.

## 1. 시간정지 게이지 회복 방식 ✅ 확정

```text
자동 회복: 공격 버튼에서 손을 떼면 자동으로 차오름
처치 보너스: 적 처치마다 즉시 +20% 회복
게이지가 없어도 손을 떼면 공격(돌진)은 발동
```

## 2. 슬로우 게이지가 0이 되었을 때의 정확한 처리 ✅ 확정

```text
슬로우는 풀림
공격 조준 상태는 유지 (공격 범위 계속 표시)
손을 떼면 공격 발동
```

## 3. 공격 타입 선택 UI

프로토타입에서는 게임 시작 전 선택으로 정했지만, UI 형태는 미정입니다.

```text
단순 버튼 2개
카드 선택
무기 선택처럼 표현
```

## 4. 사망 후 재시작 위치

프로토타입에서는 1층부터 재시작이 단순하지만, 확정은 필요합니다.

```text
1층부터 재시작
현재 층에서 재시작
최고 도달 층 기준 중간 재시작
```

# 최종 정리

이 프로토타입은 복잡한 성장이나 콘텐츠보다, **핵심 액션의 손맛**을 검증하는 것이 가장 중요합니다.

가장 중요한 핵심은 이것입니다.

```text
공격 버튼을 누른다
시간이 느려진다
공격 범위가 보인다
손을 뗀다
적에게 돌진한다
한 방에 죽인다
다시 뛰어오른다
다음 층으로 간다
```

이 흐름이 재미있으면 게임의 중심은 성공입니다.  
반대로 이 흐름이 답답하면, 적 종류나 성장 시스템을 늘려도 게임이 살아나기 어렵습니다.

따라서 첫 프로토타입의 목표는 명확합니다.

**직선형/부채꼴형 슬로우 돌진 공격이 모바일에서 재미있는지 확인하는 것.**
