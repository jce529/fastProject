# 탑 등반 액션 프로토타입

# Room Prototype Design Document (2D Side-Scrolling Version)

> 본 문서는 실제 스테이지 설계 문서가 아니다.
>
> 현재 단계의 Room은 게임의 핵심 재미를 검증하기 위한
> **Action Mechanic Validation Room** 이다.
>
> 모든 Room은 2D 횡스크롤 액션 게임 기준으로 설계된다.
>
> 목표는 하나의 핵심 재미를 독립적으로 검증하는 것이다.

---

# 설계 원칙

각 Room은 플레이어에게 하나의 질문을 던진다.

```text
공격이 재미있는가?

구르기가 재미있는가?

등반이 재미있는가?

회피가 재미있는가?

연속 처치가 재미있는가?

게이지 관리가 재미있는가?
```

프로토타입 단계에서는 여러 요소를 섞지 않는다.

```text
Combat Room
→ 공격만 검증

Dodge Room
→ 구르기만 검증

Ladder Room
→ 등반만 검증
```

# Room_Combat

## 컨셉

순수 전투

## 플레이 질문

```text
공격 자체가 재미있는가?
```

## 구조

```text
┌──────────────────────────┐

        E      E

                E

P

────────────────────────────
```

## 특징

- 넓은 평지
- 장애물 없음
- 낙사 없음
- 전투 집중 구조

## 적 구성

```text
근접 적 3~5마리
```

## 검증 요소

```text
공격 타격감
슬로우 모션
히트 프리즈
자동 타겟팅
```

# 실제 개발 단계

현재 Room은 완성 스테이지가 아니다.

```text
Validation Room
↓
복합 Room
↓
실제 스테이지
↓
탑 전체 구조
```

예시

```text
Combat
+
Sniper
+
Gap
+
LadderDanger
+
Recovery
```

↓

```text
1층 스테이지 완성
```

# 최종 목표

모든 Room은 플레이어에게 질문을 던져야 한다.

```text
싸울 것인가?

피할 것인가?

구를 것인가?

돌진할 것인가?

게이지를 사용할 것인가?

아껴둘 것인가?
```

이 질문에 답하는 과정 자체가 재미있다면 프로토타입은 성공이다.
